은행 이름을 고르는 칸에 `ㄱㅁ` 만 쳐도 "KB국민은행" 이 나오면 편합니다. 한국 서비스에서는 꽤 익숙한 동작인데, 직접 만들려면 한글이 컴퓨터 안에서 어떻게 놓여 있는지부터 알아야 합니다.

React 디자인 시스템 [BestOW UI](https://bestow-ui.com/) 의 Combobox(검색해서 고르는 목록)에 초성 검색을 넣으면서 정리한 내용입니다. 코드는 실제 소스(`@bestow-ui/korean-utils` 의 `hangul.ts`)에서 가져왔습니다.

## 한글 음절은 계산으로 나눌 수 있다

유니코드는 완성형 한글 음절 11,172자를 `가`(U+AC00)부터 `힣`(U+D7A3)까지 **규칙적인 순서**로 놓았습니다. 초성 19개 × 중성 21개 × 종성 28개(받침 없음 포함) 순서입니다. 그래서 글자 코드에서 `가` 를 빼면 나머지 계산만으로 초성·중성·받침 번호가 나옵니다.

- 중성 21 × 종성 28 = **588** 글자마다 초성이 하나씩 바뀝니다.
- 종성 **28** 글자마다 중성이 하나씩 바뀝니다.

```ts
const SYLLABLE_START = 0xac00;
const SYLLABLE_END = 0xd7a3;
const CHOSEONG = 'ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ';

function decompose(char: string | undefined): Syllable | null {
  if (!char) return null;
  const code = char.charCodeAt(0);
  if (code < SYLLABLE_START || code > SYLLABLE_END) return null;
  const offset = code - SYLLABLE_START;
  return { cho: Math.floor(offset / 588), jung: Math.floor((offset % 588) / 28), jong: offset % 28 };
}
```

`국` 을 예로 들면 `0xAD6D − 0xAC00 = 365` 입니다. `365 / 588` 의 몫 0 이 초성 `ㄱ`, `365 % 588 / 28` 의 몫 13 이 중성 `ㅜ`, `365 % 28 = 1` 이 받침 `ㄱ` 입니다.

초성만 뽑는 함수는 이 계산을 글자마다 하면 됩니다. 한글 음절이 아닌 글자(영문·숫자·공백·낱자모)는 그대로 둡니다.

```ts
getChoseong('국민은행'); // 'ㄱㅁㅇㅎ'
getChoseong('KB국민');   // 'KBㄱㅁ'
```

## 초성으로 찾기

처음에는 `getChoseong(이름).includes(검색어)` 로 충분해 보입니다. 하지만 이러면 `국ㅁ` 처럼 음절과 초성을 섞어 친 검색어를 찾지 못합니다. 그래서 검색어를 한 글자씩 이름과 맞춰 보며, **초성만 친 글자는 그 자리 음절의 초성과 비교**하게 했습니다.

```ts
// 초성만 친 글자: 그 자리 음절의 초성과 같으면 맞음
if (CHOSEONG.includes(q) && choseongOf(c) === q) continue;
```

이렇게 하면 `ㄱㅁ`, `국ㅁ`, `국민` 이 모두 "KB국민은행" 에 맞습니다. 대소문자와 앞뒤 공백은 무시해서 `kb` 로도 찾습니다.

## 놓치기 쉬운 것: 아직 조합 중인 글자

한글 입력기는 글자를 **조합하는 동안에도** 입력창의 값을 바꿉니다. "국민" 을 치는 도중 입력창 값은 `ㄱ` → `구` → `국` → `국ㅁ` → `국미` → `국민` 순서로 바뀝니다. 그리고 검색은 이 값이 바뀔 때마다 돕니다.

그래서 아무 처리를 하지 않으면 `국미` 를 친 순간 목록이 **비었다가**, 받침 `ㄴ` 을 치면 다시 나타납니다. 이름에 "국미" 라는 글자는 없으니까요. 치는 동안 목록이 깜빡입니다.

그래서 **검색어의 마지막 글자**에만 두 규칙을 더했습니다.

1. 받침을 아직 안 쳤다: 초성·중성이 같으면 맞음. `국미` 가 "국민" 에 맞습니다.
2. 친 받침이 다음 글자의 초성이 된다: `한` 을 친 사람은 "하나" 를 치는 중일 수 있습니다. 받침 `ㄴ` 이 다음 글자 "나" 의 초성과 같으면 맞음.

```ts
const isLast = j === query.length - 1;
const qs = decompose(q);
const cs = decompose(c);
if (isLast && qs && cs && qs.cho === cs.cho && qs.jung === cs.jung) {
  // 조합 중 "미" → "민": 받침을 아직 안 쳤다
  if (qs.jong === 0) continue;
  // 조합 중 "한" → "하나": 친 받침이 다음 글자의 초성이 될 자음이다
  if (cs.jong === 0 && choseongOf(target[t + 1]) === JONGSEONG[qs.jong]) {
    t++;
    continue;
  }
}
```

마지막 글자에만 쓰는 이유는, 그 앞 글자들은 이미 다 쳐서 확정됐기 때문입니다. `구민` 은 "국민은행" 에 맞지 않고, `한ㅇ` 은 "하나은행" 에 맞지 않습니다.

| 신한은행   | `ㅎㅅ` | 틀림 | 순서가 다름                                |

## 정리

- 한글 음절은 `(코드 − 0xAC00)` 을 588·28 로 나누면 초성·중성·받침 번호가 나옵니다.
- 초성 검색은 "초성 문자열에 포함되는가" 보다, 검색어를 한 글자씩 맞춰 보며 초성만 친 글자를 따로 비교하는 쪽이 음절과 섞인 검색어까지 찾습니다.
- 입력기는 조합 중인 글자로도 검색을 부릅니다. **마지막 글자**를 너그럽게 맞추지 않으면 치는 동안 목록이 깜빡입니다.

이 함수는 [`@bestow-ui/korean-utils`](https://www.npmjs.com/package/@bestow-ui/korean-utils) 의 `matchesKorean`·`getChoseong` 으로 공개되어 있고, BestOW UI 의 Combobox 가 기본 필터로 씁니다. [소개 사이트](https://bestow-ui.com/) 첫 화면의 "정산 은행" 칸에 `ㄱㅁ` 을 쳐 보면 바로 확인할 수 있습니다.
