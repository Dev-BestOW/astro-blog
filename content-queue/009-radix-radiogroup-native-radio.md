라디오 묶음은 화살표 키로 다룹니다. 포커스가 다음 항목으로 옮겨지면서 **그 항목이 바로 선택**되는 것이 기본 동작입니다(WAI-ARIA 라디오 그룹 패턴, 브라우저 기본 라디오도 같습니다).

React 디자인 시스템 [BestOW UI](https://bestow-ui.com/) 의 RadioGroup 은 처음에 Radix 의 RadioGroup 위에 스타일만 입혔습니다. 그런데 E2E 테스트에서 **포커스는 옮겨졌는데 선택이 안 되는** 경우가 나왔습니다.

## 재현: 키를 바로 떼면 선택이 빠진다

먼저 비슷한 컴포넌트에서 증상을 봤습니다. 정렬 방식을 고르는 SegmentedControl 을 Radix RadioGroup 위에 만들었는데, 화살표를 빠르게 연달아 누르면 약 20% 확률로 선택이 빠졌습니다. 이건 직접 구현(버튼 묶음)으로 바꿨습니다.

같은 문제가 RadioGroup 에도 있는지 E2E 로 재현해 봤습니다. **키를 눌렀다 바로 떼는 화살표 입력**에서 **20회 중 19회** 선택이 빠졌습니다.

원인은 Radix RadioGroup 이 선택을 정하는 방식이었습니다. 포커스가 옮겨질 때 **화살표 키가 아직 눌려 있는지**(문서의 keydown/keyup 으로 추적)를 보고, 눌려 있을 때만 선택합니다. 사람이 키보드를 누를 때는 대개 키가 눌린 채로 포커스가 옮겨지니 문제가 드러나지 않습니다. 하지만 키를 아주 짧게 누르는 입력에서는 포커스가 옮겨질 때 이미 keyup 이 지나가 있어 선택이 빠집니다. Playwright 의 `press`, user-event, 그리고 일부 보조기기의 입력이 그렇습니다. 단위 테스트 환경(jsdom)에서는 늘 빠졌습니다.

키보드 사용자를 위한 컴포넌트가 입력 속도에 따라 다르게 동작하면 안 됩니다. 그래서 네이티브 `<input type="radio">` 로 다시 만들었습니다. 브라우저 기본 라디오는 화살표로 옮기면 그 항목이 바로 선택됩니다.

## 네이티브로 바꾸며 챙긴 것

공개 API(props·ref)는 그대로 두고 안쪽만 바꿨습니다. Radix 의존성 하나가 빠졌습니다.

### 1. name 이 없을 때의 묶음

브라우저는 **같은 `name`** 을 가진 라디오끼리 한 묶음으로 화살표 이동합니다. 그런데 컴포넌트를 쓰는 쪽이 `name` 을 주지 않을 수도 있습니다(폼 제출 없이 상태로만 쓰는 경우). 그래서 이름을 만들어 묶되, **그 이름이 폼에 제출되지 않게** 존재하지 않는 form id 를 가리키게 했습니다(실제 코드).

```ts
// 브라우저는 같은 name 끼리 한 묶음으로 화살표 이동한다. name 을 안 받았으면 만든 이름으로 묶되,
// 그 이름이 폼에 제출되지 않게 존재하지 않는 form id 를 가리켜 폼에서 뗀다(같은 "폼 없음" 끼리라 묶음은 유지된다).
const groupName = name ?? `${baseId}-radio`;
const detachedForm = name ? undefined : `${baseId}-no-form`;
```

`name` 을 주면 그대로 폼에 제출되어, react-hook-form 의 `register` 나 서버 액션과도 바로 이어집니다.

### 2. 모양은 다시 그리고, 고대비에서는 되돌린다

브라우저마다 다른 기본 모양 대신 디자인에 맞추려고 `appearance: none` 으로 지우고, 선택 점은 배경색 + 안쪽 그림자(`inset box-shadow`)로 그렸습니다. 그런데 Windows 고대비 모드는 그림자를 지웁니다. 그래서 그 모드에서만 `appearance: auto` 로 **브라우저 기본 라디오로 되돌립니다.** 운영체제가 그리는 컨트롤은 고대비에서 알아서 보입니다.

### 3. 테스트도 바꿔야 한다

네이티브 라디오에는 `aria-checked` 속성이 없습니다(상태가 `checked` 속성에 있습니다). Radix 때처럼 `aria-checked="true"` 를 확인하던 테스트는 모두 실패합니다. 단위 테스트는 `.checked`, Playwright 는 `toBeChecked()` 로 바꿨습니다.

### 4. 브라우저마다 다른 기본 동작

네이티브로 가면 브라우저 차이도 그대로 따라옵니다. E2E 를 쓰며 만난 것들입니다.

- **Safari(WebKit)는 라디오를 클릭해도 포커스를 주지 않습니다.** 테스트에서 클릭 뒤 화살표를 누르려면 포커스부터 줘야 합니다.
- **Safari 의 네이티브 라디오는 끝에서 처음으로 돌지 않습니다.** 마지막 항목에서 →를 누르면 그대로입니다.

그래서 E2E 는 이런 차이에 기대지 않게 썼습니다. 브라우저 이름으로 분기하는 코드는 최소로 둡니다.

```ts
// Radix RadioGroup 을 쓸 때는 키를 바로 떼는 입력에서 포커스만 옮겨지고 선택이 빠졌다(20회 중 19회) — 네이티브 radio 로 바꿨다
test('RadioGroup: 화살표로 옮기면 바로 선택되고, 지연 없이 연달아 눌러도 매번 선택된다', async ({ page }) => {
  await page.goto('/interactive');
  const group = page.getByRole('radiogroup', { name: '결제 주기' });
  const monthly = group.getByRole('radio', { name: '월간' });
  // macOS Safari 는 라디오를 클릭해도 포커스를 주지 않는다(플랫폼 동작) — 키보드 사용자처럼 포커스부터 준다
  await monthly.click();
  await monthly.focus();
  // … 화살표를 지연 없이 연달아 누르고, 매번 선택됐는지 확인한다(줄인 코드)
});
```

## 결과

- 같은 E2E 를 **20회 반복해 모두 통과**했습니다(바꾸기 전 19회 실패).
- 새 단위 테스트 6개는 구현을 일부러 망가뜨려 실패하는지 확인했습니다.
- 시각 회귀: macOS 에서 이전 커밋과 픽셀 차이 0. 다만 Linux 기준 이미지에서는 선택 점 가장자리의 안티앨리어싱이 조금 달라(0.03%) 기준 이미지를 갱신했습니다.

## 정리

- Radix RadioGroup 은 **포커스가 옮겨질 때 화살표 키가 눌려 있는지**로 선택합니다. 키를 아주 짧게 누르는 입력(테스트 도구, 일부 보조기기)에서는 선택이 빠질 수 있습니다.
- 브라우저 기본 라디오는 이 문제가 없습니다. `appearance: none` 으로 모양만 다시 그리고, 고대비에서는 `appearance: auto` 로 되돌립니다.
- `name` 이 없을 때는 만든 이름 + 존재하지 않는 form id 로 묶음은 유지하고 제출에서는 뺍니다.
- 네이티브로 바꾸면 `aria-checked` 가 사라지고 브라우저 차이가 생기니 테스트도 함께 바꿉니다.
- 무엇보다, **E2E 를 여러 번 반복**해 봐야 이런 확률적인 문제가 보입니다. 새 E2E 는 `--repeat-each 5` 정도로 돌려 안정적인지 먼저 확인합니다.
